# Contributing

Contributions should improve scientific clarity, provenance, reproducibility or software correctness. Run the locked test, lint, typing and public-data checks. Submit code changes with their observed verification results. Model inference is optional and separately budgeted; pull requests must not require paid credentials.

New cases start as original draft candidates, with a narrow stated objective, explicit premises, a proposed label, exact evidence spans, source support and rights information. A proposed positive case is not gold. Link all related variants, templates and source-derived material before assigning splits. Never submit held-out protocol text, reference answers, reviewer identity mappings, API keys or private raw model artifacts to a public pull request. Private cases require the study's private curation process.

Case edits must preserve exact controlled-edit provenance. If a natural four-way family is impossible, retain fewer variants and document the scientific reason; do not force a severity label. Add a regression test for a meaningful software behavior, not a test that treats an unreviewed chemistry label as validated truth. Automated-test reviewer identities are synthetic fixtures and must never be exported as scientific annotation.

Changes affecting scientific evaluation need a versioned policy decision and renewed review where relevant. Do not tune issue dictionaries, thresholds or prompts on held-out answers. Document deviations and uncertainties rather than optimizing reported results retrospectively.
